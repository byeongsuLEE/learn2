# generics
 여러 타입을 받고 싶을 때, 타입의 안정성을 보장하고 싶을 때 사용합니다.
 

## generics 동작 방식
1. 컴파일러는 작성된 소스 코드를 읽고 분석합니다.
2. 제네릭 정보를 활용해 엄격한 타입 안정성 검사를 수행합니다. 이때 타입이 일치되지않으면 컴파일 에러를 발생시킵니다.
3. 타입 검사 성공 후, 컴파일러는 모든 <..> 제네닉 타입 정보를 지워 버립니다. ( 타입 소거)
4. 제네릭 정보가 사라진 코드가 바이트코드(.class) 파일로 변환 되빈다.
5. 이 바이트코드에서 List<String>은 -> List<Object>가 됩니다.
6. 바이트 코드를 jvm이 제네릭 정보가 소거된 .class  파일을 읽어들입니다.
7. jvm은 제네릭이 없는 일반적인 코드처럼 프로그램을 실행합니다.
8. 자동 형변환을 통해 타입 소거 과정에서 컴파일러가 자동으로 삽입했던 형 변환 코드를 통해 list.get(0) 과 같이 Object 변환된 값을 String 으로 안전하게 변환하여 사용할 수 있습니다.


## 상한 extends A
최대 A 까지 허용한다.
A와 A의 자손들의 타입만 허용합니다.

## 하한 super A
적어도 A까지는 되어야한다.
A와 A의 부모,조상들의 타입만 가능합니다.

super (하한 경계)	상향식 (아래 -> 위)	아래쪽을 제한	데이터를 추가하기 위해 (쓰기)
extends (상한 경계)	하향식 (위 -> 아래)	위쪽을 제한	데이터를 가져오기 위해 (읽기)
